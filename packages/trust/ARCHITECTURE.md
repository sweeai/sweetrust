## High-level architecture

One package, three primitives, one direction of flow:

```
  sweetrust/mandate  ──▶  sweetrust/gate  ──▶  sweetrust/verify
   issue authority        enforce it at         prove it happened
   in bounded tiers       the sink boundary     to a stranger
```

Each is independently importable — the arrows are how they *compose*, not what they *require*. `gate` has no knowledge of `mandate`. `verify` is the only one that reaches across, and it reaches for exactly one thing: mandate's signer, so the rail has one canonicalization rather than two that drift.

1. **Authority** (`src/mandate/`) — issue, use, revoke, across organization → project → agent tiers. Subset gates enforced by the compiler and re-checked at runtime. Every act on an Ed25519-signed hash chain.
2. **Enforcement** (`src/gate/`) — `Sourced<T>` provenance tags, the three-tier lattice (`untrusted → corroborated → verified`; the spec's `asserted` rung was never produced and was removed 2026-10-13), three declassifiers as the only ascent paths, fail-closed sinks, the judgment seam, and the receipt log.
3. **Evidence** (`src/verify/`) — signs gate's receipts *through* mandate's signer, exports JSONL, and re-verifies from public material alone plus an optional on-chain anchor.
4. **Adapters** — anything needing a network lives outside the package. Keeping adapters out is what makes the zero-dependency claim true.

**Dependency injection without a framework.** The `makeXLive` naming survives from an Effect-TS era that ended 2026-07-20 (DAN-600). These are now plain factory functions returning plain service objects. The *discipline* is unchanged — tests and production run identical calling code and differ only in which factory was wired at the entry point — but there is no Effect runtime, no `Layer`, no `Tag`, and no fiber. Do not reintroduce them.

## Data flow

Core: issue/use/revoke → `MandateAudit.record` → `MandateSigner.sign` (Ed25519 over the full envelope + previousHash) → `SignedMandateAuditEvent` → `verifyAuditChain`.

Enforcement: extraction boundary → `Sourced` tag → (optional declassifier) → sink appetite check → `ReceiptLog.append` → (with verify wired) Ed25519 signature + wrapper chain → JSONL → `verifySignedChain`.

### 2. Mandate flow (issue / use / revoke)

- **STATUS:** LIVE
- **FLOW:** three tier-specific issuers (`issueOrgMandate` → `issueProjectMandate` → `issueAgentMandate`) with per-tier compile-time subset gates, plus `useCapability` and `revokeMandate`. The v0.0 pair `issueRootMandate` / `issueMandate` was kept alongside them, deprecated, until the 2026-10-13 rail audit removed it: it stamped `"organization"` on everything it minted, so an organization's child claimed to be an organization. Agent-tier mandates are leaves — type system structurally refuses upward delegation. **Post-2026-05-07 audit pass**, three runtime gates strengthened: (a) `useCapability` rejects if ANY ancestor is revoked (`AncestorMandateRevoked` error); (b) `useCapability` requires a `grant` event in the audit log AND verifies claimed capabilities are a subset of granted capabilities (`MandateNotIssued` / `MandateScopeForged` errors close the forged-scope-literal bypass); (c) all child issue functions call `audit.isRevoked(grantorScope.id)` before recording (closes the revoke-vs-issue race that produced orphan children). `useCapability`'s signature generalized to `<Caps, Cap, Tier, ParentScope>` so multi-tier mandates can be invoked directly without type gymnastics. **Post-2026-07-22 battle-test (DAN-637):** gate (a) now reconstructs the ancestor chain from the AUDIT LOG via each grant event's `parentMandateId` (walking up from `mandate.id`, the same primitive `revokeMandate` uses), NOT from the in-memory `parentScope` pointer. The pointer was not load-bearing truth — the then-live `issueMandate` set `parentScope: null`, deserialized mandates lose the object graph, and a forged `{...realScope, parentScope: null}` severed the walk — so revoking a root never disabled a child and the org kill-switch was silently inert. `parentScope` no longer participates in any security decision; the `AnyMandateScope` alias was removed.
- **SOURCE:** `src/mandate/mandate.ts`. Type-level subset gate: `Cap extends Caps[number]` (v0.1.1 fix; load-bearing per LESSONS) generalized to walk the parent-tier chain in `issueProjectMandate` (`ProjectCaps extends ReadonlyArray<OrgCaps[number]>`) and `issueAgentMandate` (`AgentCaps extends ReadonlyArray<ProjectCaps[number]>`). Runtime fallback subset check handles any-cast escape hatches. **Post-2026-07-22 (DAN-639):** the in-memory fallback is backed by `assertRequestedCapsBackedByGrantorGrant`, which re-checks every requested capability against the grantor's RECORDED grant event (`audit.query(grantorScope.id).find(grant).capabilities`) in all three derived issue functions — a forged in-memory `grantorScope.capabilities` can no longer mint a capability the grantor was never granted (`MandateScopeForged`; a wholly-fabricated grantor with no grant event → `MandateNotIssued`). Audit-log-is-truth now holds at issuance, not only use/verify. `generateMandateId` uses the full 16 hex characters of `crypto.randomBytes(8)`, 64 bits (it kept 10, 40 bits, until the 2026-10-13 mandate audit), and every issuer takes its id from `freshMandateId`, which draws again while the log has any event under the candidate, so an id is never minted twice into one log. Helper `checkGrantorNotRevoked` centralizes the issue-time revocation guard. Ancestor-revocation walk in `useCapability` uses `audit.query(cursorId).find(grant).parentMandateId` to climb the chain. **Post-2026-07-22 (DAN-640):** that walk fails CLOSED — a non-leaf cursor with no grant event (a tampered/truncated log that severs the chain) throws `DelegationChainBroken` instead of silently stopping, so a revoked ancestor above a broken link can't be missed; the leaf-with-no-grant case still routes to `MandateNotIssued` (legitimate forged-fake-id). **Post-2026-10-13 mandate audit:** every exported function reads each caller-supplied `args` field exactly once, at its top, into a local, and resolves each capability `key` exactly once; the checks, the mint and the record consume those locals. Before this a getter on `args` could present the genuine scope to `assertIssued` and forged data to every other read, and four escalations followed from a held leaf alone (invoke an unheld capability under another id; mint a project outside the subtree; revoke the org root through `mandateId`; mint a child carrying a capability outside its grantor's grant). The last describe block of `test/mandate/authority-binding.test.ts` pins the read count at one per field for all five object-taking exports (three issuers, `useCapability`, `revokeMandate`). Capability identifiers pass `constitutionalPreCheck` before persistence, in `defineCapability` and again in every issuer.
- **LAST VERIFIED:** 2026-10-13 (`test/mandate/authority-binding.test.ts` incl. the audit's getter-split block, `test/mandate/security.test.ts`, `test/mandate/mandate-id.test.ts`; build, tsc, readme-typecheck and forgery-typecheck green; the auditor's seven reproduction scripts re-run against `dist/`, every split refused). Prior: 2026-07-22 (`test/mandate/audit-log-is-truth.test.ts`: ancestor + cycle-guard + issue-time forged-grantor + broken-chain fail-closed regressions; 0 typecheck errors).

### 3. Audit log (unsigned + signed)

- **STATUS:** LIVE
- **FLOW:** Two parallel factory families sharing the same `MandateAuditService` interface for record/query/isRevoked. Unsigned (`makeInMemoryAuditLive`, `makeJsonlAuditLive`) records raw `MandateAuditEvent` objects. Signed (`makeInMemorySignedAuditLive`, `makeJsonlSignedAuditLive`) wraps every record in `SignedMandateAuditEvent` using an injected signer; previousHash chains records via SHA-256 of canonical JSON. The `read → sign → append` critical section must not interleave, or two recorders observe the same chain head and fork the chain. **Mechanism changed 2026-07-20 (DAN-600):** the Effect version guarded it with a single-permit `Effect.makeSemaphore(1)`; the plain-TS rewrite is fully synchronous, so the critical section is inherently serialized and no lock is needed (the `makeInMemorySignedAuditLive` doc comment in `src/mandate/audit.ts` states this at the site). **The property is unchanged; only its enforcement is.** The JSONL family's cross-process append is NOT locked — single writer per store. **Both JSONL stores read fail-closed** through one shared `readJsonl`: a corrupt line throws `AuditLogCorrupt` from every read (including a direct `isRevoked`, which must never read a wrecked log as "not revoked"), and only a missing file is an empty log. The signed JSONL store additionally re-verifies the whole file against the signer's key on every read, and refuses to append past corruption.
- **SOURCE:** `src/mandate/audit.ts`. Both signed factories return `{ mandateAudit, signedAudit }`, two views of ONE store (an array in memory, the file for JSONL), so state stays consistent across them. That is what makes the signed store usable as THE audit log: before 2026-09-23 the JSONL signed factory returned only the signed surface, so a host needing `isRevoked` had to pick the unsigned store.
- **LAST VERIFIED:** 2026-05-07 for the chain semantics (multi-tier-demo runs end-to-end with a 4-event signed chain; `verifyAuditChain` returns valid:true on intact, signature-mismatch on tamper, hash-chain-broken on removal). **Serialization mechanism re-verified 2026-07-30** against the merged source. **Fail-closed reads and the two-view signed JSONL store verified 2026-09-23** (`test/mandate/durable-signed-audit.test.ts`).

### 4. Cryptographic signer

- **STATUS:** LIVE
- **FLOW:** Two production signer factories (`makeEd25519SignerLive`, `makeEd25519VerifierLive`, the latter new at 2026-05-07) and one test signer (`makeInMemorySignerLive`). *(Formerly an Effect Tag with three Layers; plain factories since DAN-600.)* **Payload-generic since v1.1.0 (2026-07-07):** `sign`/`verify` accept any payload `P` and return `Signed<P>` (`SignedMandateAuditEvent` is now the alias `Signed<MandateAuditEvent>`); the signer signs canonical bytes and never inspects payload structure, so external record types (first consumer: SweeVerify receipts, `src/verify/verify.ts`) share this one implementation. `makeInMemorySignerLive` produces test signatures (`inmem-<sha256>` of the signed preimage) for tests + non-cryptographic demos; they are a pure function of the envelope, and since the envelope includes `signedAt` two `sign()` calls on one payload differ, so they are not deterministic across calls (see the `signedAt`-in-preimage note at the definition). Its marker is refused if it parses as an SPKI key (2026-10-13). `makeEd25519SignerLive(config)` uses `node:crypto` Ed25519 primitives; signs the canonical JSON of the ENVELOPE (`signedPreimage`: domain + payload + previousHash + signedAt), not the payload alone; verifies against the per-record `signerPublicKeyHex` (NOT the factory's own key). Both Ed25519 factories validate their key material at construction (ed25519 only, a matched pair, no PRIVATE PEM in a public slot; 2026-10-13). `makeEd25519VerifierLive(config)` is the verifier-only factory, added 2026-05-07 — accepts `publicKeyPem` only; `sign()` throws with a programmer-error message; `verify()` works against the per-record key. Closes spec mandate-v0-2 reconstruction-test #8 (cross-process audit verification). The per-record-key verify pattern enables external auditors to validate chains without holding signing authority + future key rotation (v0.2.1 per spec I11).
- **SOURCE:** `src/mandate/signer.ts`, which re-exports `canonicalJSON` and `sha256Hex` from `src/canon.ts` (moved there in the 2026-10-13 rail audit; a leaf importing only `node:crypto`, so gate's receipt hash can share it without importing mandate). `canonicalJSON` is a recursive sort-keys + no-whitespace serializer ( sufficient for `MandateAuditEvent` — strings/null/literals — AND for JS-only generic payloads containing Numbers, since ECMAScript fully specifies number→string serialization and both sign/verify sides run JS; BigInt/Date/NaN payloads would throw or drift — upgrade to RFC 8785 / JCS before any cross-language verifier consumes these chains) and `sha256Hex` helpers. `verifyAuditChain` walks a log and returns `{ valid, firstInvalidIndex, reason, detail? }`, the reason covering `signature-mismatch`, `hash-chain-broken`, `missing-signature`, `untrusted-signer` (2026-07-22), `domain-mismatch`, `empty-chain` and `malformed-record` (a non-record, a bad key or signature encoding, a value canonicalJSON cannot encode, a key outside the six-field envelope, a getter that throws). `signerPublicKeyHex` is hex-encoded SPKI-DER (~88 hex chars / ~44 bytes), NOT raw 32-byte (a cross-runtime verifier such as browser WebCrypto must strip the ASN.1 wrapper itself; a `rawPublicKeyHex` field is a candidate addition). **Post-2026-07-22 battle-test (DAN-638):** `verifyAuditChain` takes a REQUIRED `opts.trustedSignerPublicKeyHex` and rejects any record whose `signerPublicKeyHex` differs *before* the signature check (`untrusted-signer`). Verifying against the record's OWN embedded key proves internal consistency, not authorship — an attacker who obtained the log could re-sign every record under their own key and pass. The trust root is now a key pinned out-of-band by the caller, mirroring `sweetrust/verify`'s `verifySignedChain`. Per-record `verify()` still uses the embedded key (that is what makes verifier-only factories and future key rotation work); the pinning gate sits above it in `verifyAuditChain`.
- **LAST VERIFIED:** 2026-10-13 verify audit (`test/verify/adversarial-envelope.test.ts`, `test/mandate/adversarial-audit-chain.test.ts`): the six-key envelope is pinned on every record, the pin gate refuses a non-string pin, each field is read once, Ed25519 signatures are shape-checked before decoding, key material is validated at construction, and `canonicalJSON` now matches JSON.stringify on boxed primitives and nested / key-reading `toJSON`. (Prior: 2026-07-22, attacker-key-substitution + cycle-guard regressions; 2026-07-07 + 2026-05-07 checks all still covered by the suite.)

### 9. Enforcement kernel — `sweetrust/gate`

- **STATUS:** LIVE
- **FLOW:** Extraction boundary → `Sourced<T>` tag carrying tier + provenance (origin, ancestry, audit chain, optional confidence) → tags propagate through combination, taking the **minimum** tier (Rule 1: taint is sticky) → optionally through one of exactly three declassifiers (Rule 3) → sink appetite check (Rule 4, fail-closed) → judgment seam → `ReceiptLog.append`. Every SINK decision lands on the log, allow *and* refuse. Two gaps are documented in `SECURITY.md` § *Honest limits*: a declassifier's refusal leaves no receipt (`"declassify-refused"` is reserved, not produced), and neither does an action whose signer throws after `execute()`. `fromLLM` returns untrusted unconditionally (Rule 2: inference is not evidence). Adoption ladder `observe → warn → enforce` (Rule 5) lets it be installed into a running system without breaking it.
- **SOURCE:** `src/gate/trust.ts` — one file, deliberately, so the kernel is auditable in a sitting. The `Sourced` constructor and `ascend` are **module-private** — at runtime too, since 2026-10-13: the constructor demands a module-private token and throws without it, and the class and its prototype are frozen. `allowlisted` / `corroborate` / `humanConfirm` are the only doors. Zero dependencies, `node:crypto` only.
- **Architecture Invariant — a check and the promotion it authorizes name the SAME binding.** `allowlisted` returns the **registry's** `Sourced`, never the caller's candidate. The candidate is compared and then discarded; its identity survives only in the ascent event's `evidence`. This is not a style preference: serialization is not identity, so a candidate can compare equal and *be* something else, and promoting the compared-against record is what makes the comparison mean anything. Callers must not assume they get their own object back.
- **Architecture Invariant — an ABSENCE: nothing in the sink path reads a key off a prototype.** Membership is `Object.hasOwn`, never `in`; the receipt's `args` bag and the judgment provider's bag are `Object.create(null)`, never `{}`; redaction policy is read through an own-key helper; and `makeSink` reads its own spec by own key, once, at construction, so a polluted `Object.prototype.redact` or `.judgment` reaches no sink (2026-10-13). Argument names are chosen by whoever wrote the tool schema — which, for this package's stated target, is not us. An argument named `constructor` or `__proto__` must be as visible to enforcement as one named `amount`.
- **Architecture Invariant — the sink acts on the binding it checked.** `execute()` and the judgment provider receive one null-prototype snapshot of the declared arguments, each read once at check time. An undeclared argument is recorded and raised but never reaches the action, in any mode. The 2026-08-31 rule for `allowlisted`, applied to the sink on 2026-10-13: a getter that answers one value when checked and another when used must find nobody reading it twice.
- **Architecture Invariant — caller input is read once, at the boundary** (`AGENTS.md` § Non-negotiables, "Intake"). Every object-taking export in all three subpaths snapshots each field of its argument once and acts on the snapshot. `test/intake-poison.test.ts` runs each of them under a Proxy that throws on a second read (`test/helpers/poison.ts`) and requires the plain object's verdict. On 2026-10-13 it caught `ReceiptLog.append` spreading its entry twice (hashed body and committed receipt from separate reads), `verifyAuditChain` reading its pin once per record, and the three declassifiers re-reading their `Sourced` arguments into the ascent; all four are single-read now.
- **Architecture Invariant — the receipt hash is over canonical bytes.** `receiptBody` is `canonicalJSON` (`src/canon.ts`) over the receipt's seven fields, keys sorted at every depth. The interior hash therefore depends on a receipt's VALUES and on nothing about how its JSON was laid out, the same property the signature and the wrapper link already had. Until the 2026-10-13 rail audit it was `JSON.stringify` with a hand-pinned top level, and the `args` tree underneath followed insertion order (`docs/adr/0002`).
- **TCB honesty:** in-process TypeScript is observe/warn/dev-time authority. Code that can import this module and lie about an authority name can mint verified values. In-process TypeScript cannot be unforgeable. Money limits belong to the chain's own primitives (on Sui, native `sui::allowance`); this package's `revokeMandate` writes only to this log. The honest-limits comment block in the source is load-bearing — do not remove it.
- **LAST VERIFIED:** 2026-10-13 adversarial audit of the gate against built `dist/` — **twenty findings: 1 HIGH (the sealed ancestry Set leaked its raw self through `forEach`), 6 MEDIUM, 13 LOW/DOC — all twenty closed**, each regression watched red against the pre-fix source before its fix, the auditor's 19 exploit scripts re-run against the rebuilt `dist/` and every one now stops where it used to mint or execute. The record is `test/gate/audit-2026-10-13.test.ts`. (Prior: 2026-08-31 pre-publish audit — two unconditional fail-opens in `enforce` mode against built `dist/`, both invisible to the suite of the day, both closed, `test/gate/trust.test.ts`. 2026-07-25 pass, five fail-opens closed, `test/gate/adversarial-enforcement.test.ts`.)

### 10. Evidence kernel — `sweetrust/verify`

- **STATUS:** LIVE
- **FLOW:** Wraps gate's `ReceiptLog` with authorship. `SignedReceiptLog extends ReceiptLog` and drops into `makeSink`'s `log:` — wrap, never fork. Each receipt is Ed25519-signed at append time through mandate's signer. **Two chains, both checked:** the interior kernel chain (`Receipt.prevHash`/`hash`, computed by gate) and the wrapper chain (`Signed.previousHash = sha256(canonicalJSON(previous signed record))`, per mandate audit-chain semantics, spec I8). `exportJSONL` produces the artifact handed to an auditor; `verifySignedChain` re-checks every signature, both hash links, and sequence, holding only public material.
- **SOURCE:** `src/verify/verify.ts`. `trustedSignerPublicKeyHex` is **required**, not optional — verifying a record against the key it carries proves internal consistency, not authorship. Interior-hash recomputation calls gate's `receiptBody`, which is `canonicalJSON` over the receipt (`src/canon.ts`, since the 2026-10-13 rail audit), so the interior hash, the wrapper link and the signature are all over canonical bytes and an artifact re-serialized with sorted keys verifies as written. Changing the receipt's field set is still a cross-subsystem, hash-breaking change (`docs/adr/0002`).
- **Honest limits (proven by tests, not asserted):** tail truncation leaves a valid shorter chain and is catchable *only* by the on-chain anchor, and only by an `"anchor"` seal — a per-decision `"receipt"` memo proves the chain through its own seq, never the whole chain. A compromised host can sign lies going forward; it cannot rewrite the past behind an anchor or forge under a key it does not hold.
- **LAST VERIFIED:** 2026-10-13 verify audit (`test/verify/adversarial-envelope.test.ts` is the record): a seventh key on the head record is refused, the pin gate is fail-closed on its own, every field is read once and the anchor checks read the verified snapshot, a signature is 128 lowercase hex before any decoding, unknown options (the retired `anchoredHead`) are refused by name, `parseJSONL` numbers lines as the file does and accepts a BOM, `exportJSONL` escapes U+2028/U+2029/U+0085, and `RECEIPT_DOMAIN` / `signedPreimage` are exported. The one item deferred from that pass — the interior receipt hash was insertion-order JSON, so a re-serialized artifact reported `hash-mismatch` — closed the same day in the rail audit: `receiptBody` is canonical (`test/canon.test.ts`). (Prior: 2026-07-25 adversarial pass, `test/verify/adversarial-evidence.test.ts`: malformed input returns a verdict instead of throwing; merged-tree run 2026-07-30.)

### 11. Refusals — `MandateFailure`

- **STATUS:** LIVE (new in 0.4.0)
- **FLOW:** every mandate refusal is thrown as `MandateFailure`, an `Error` subclass whose own properties ARE the `MandateError` union: `_tag` first, then the variant's fields, so `e._tag` switches and `JSON.stringify(e)` read exactly as the plain union did. `message` is the `_tag` alone, because some variants carry attacker-supplied text (`MaliciousMandateMetadata.evidence` is the injected rationale itself) and a message reaches every log title and any model that reads the logs. `name` lives on the prototype, so it is not an enumerable key. `MandateFailure.is(e)` narrows a caught value. The one visible difference from the old plain object: `structuredClone(e)` keeps only an Error's standard fields, so `_tag` does not cross a worker boundary — send `{ ...e }`.
- **SOURCE:** `src/mandate/errors.ts`; thrown through `failMandate` in `src/mandate/mandate.ts` and the durable stores' `corrupt()` in `src/mandate/audit.ts`. The union itself (ten variants) is in `src/mandate/types.ts`, § 1.
- **LAST VERIFIED:** 2026-10-13 (`test/mandate/mandate-failure.test.ts`, including the ten-variant pin).
